# 专用手册：数仓空分区、枚举漂移与对账

数据从外部系统进到报表要过四层：开放平台 / webhook（接入）→ CAP + Kafka（ODS，保留 365 天）→ `materialize-worker` 流作业写 DWD（StarRocks）→ DWS 聚合作业（流层即时累加 + 批层定期校准）。这一层链路断了，页面上最先出现的不是报错，而是**空**。

来源：`tradepass.growth/docs/data-warehouse.md`。

## 1. 两条容易踩的口径

- **现网 DWS 由物化引擎的聚合作业产出，数仓里没有物化视图。** 所以「MV 刷新滞后」实际要盯的是聚合作业的产出新鲜度，不是 `SHOW MATERIALIZED VIEW` 的刷新状态。
- **数仓表不设 `partition_live_number`**：StarRocks 侧的数据不删不搬。「保留期」与声明里的「回填下界」（`backfillFloor`）不是一回事，回填下界只告诉批作业历史回溯到哪一天，不删任何数据。

## 2. 空分区

- 对象：**分区的** DWD 事实表（按天分区，`PARTITION BY date_trunc('day', event_time)`）；
- 判据：每天检查前一天分区行数是否为 0。空分区视为数据管道断链信号，触发告警；
- 不分区的表用不了分区元数据（本仓 12 张 `dwd_cst_*` 里有 10 张不分区），改按 `local_date` 分组数当天行数；
- 空分区不是「这天没有业务」，是「该到的数据没到」。先查上游 topic 当天到达量，再查流作业是否在跑、写入是否报错；
- 参考检查语句（示意）：

  ```sql
  SELECT COUNT(*) FROM dwd_{业务域}_{业务过程}_di
  WHERE partition_date = CURRENT_DATE - 1
  HAVING COUNT(*) = 0;
  ```

- 判定口径：前一天分区行数 > 0 为健康；为 0 按 `Critical` 告警。

## 3. 枚举漂移

- 白名单字段：`kyc_status`、`call_result`、`deposit_channel` 等。摄取作业写入前做白名单校验；
- 告警口径：出现白名单外的值立即告警；枚举值分布的环比变化超过阈值也告警；
- 处置顺序：先确认上游契约是否已经上线新值（新值上线是「先扩后收」，分两次发布），再决定扩白名单还是修上游；
- 不要先改 DWD 里的值：改值会把「上游契约变化」变成「历史数据被篡改」，对账时再也说不清；
- 判定口径：白名单外值个数 ≤ 0 为健康；按 `Critical` 告警。

## 4. 日量环比

- 判据：当日新增记录数与前 7 日均值的偏差超过 ±30% 触发告警；
- 偏差为负（少了 30% 以上）多半是漏写、上游断流或分区没落；
- 偏差为正（多了 30% 以上）多半是重复投递、补数或上游重放；
- 判定口径：|偏差| ≤ 0.3 为健康；按 `Warning` 进日报，连续 2 天异常升级为 `Critical`。

## 5. 聚合作业产出滞后

- 判据：DWS 聚合表最新一次成功产出的时间距今超过 120 分钟；
- 说明：现网没有物化视图，这条检查项的「MV 刷新」含义是「聚合作业产出新鲜度」；
- 滞后的常见原因：流作业消费 lag、批层校准任务没调度、StarRocks 写入失败；
- 判定口径：滞后 < 120 分钟为健康；按 `Warning` 进日报。

## 6. 归属对账

- 判据：以业务库（MySQL）的客户归属为基准，与 DWD 宽表的归属列逐客户比对，差异数必须为 0；
- 首次态列（`first_*`）只能由 `Agg.Min` / `Agg.First` / 事件投影产出。用 `Agg.Max` 或 LWW 写首次态，会把「当前态」伪装成「首次态」，对账能直接暴露；
- 差异先取证（哪一批客户、差在哪个字段、最近一次写入作业），再决定重算还是修作业；
- 判定口径：差异数 ≤ 0 为健康；按 `Critical` 告警。

## 7. 其他强制数据质量要求

- 每张 ODS / DWD 全量表必须有唯一性字段（Primary Key 或业务 Unique Key），并由数据质量任务定期检查；
- 建表必须带表级 `COMMENT` 与所有字段的 `COMMENT`，枚举字段要在注释里列出合法值；
- 上述两项属于建表准入，不在运行期检查单里判定，发现缺失按建表问题回修。

## 8. 表名与阈值口径

- 检查项里的表名与列名是 v1 mock 口径的示意；接入真实数据源时按数据字典校准，判据不变，并递增 `RuleVersion`；
- 阈值由上游流量基线决定，调阈值要走判据变更流程，不要为了变绿临时放宽。
